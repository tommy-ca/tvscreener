# Implement Robust Timeframe Mapping for MTF Parser

## Problem Statement

The `MTFExpressionParser` needs to map user-friendly shorthand expressions (e.g., `1D:RSI < 30`) to valid SQL syntax based on the actual columns generated by `DataTransformer` (e.g., `RSI_1440` or `RSI_1D`, depending on how timeframes are standardized).

## Findings

- `tvscreener` internal timeframes are typically passed as strings representing TradingView intervals (e.g., `"15"`, `"60"`, `"240"`, `"1D"`, `"1W"`).
- `DataTransformer` renames columns dynamically based on these passed timeframe strings (e.g., `f"RSI_{tf}"`).
- If a user inputs `1H:RSI`, the parser must know `1H` maps to `60` so the resulting SQL is `RSI_60`.

## Proposed Solutions

### Option 1: Regex Translation with TF Mapping Dictionary
1. Build a dictionary mapping common user aliases to TV intervals (e.g., `{'1H': '60', '4H': '240', '1D': '1440'}`).
2. The `MTFExpressionParser` should regex match `{TF}:{FACTOR}` and apply the translation dictionary before constructing the final SQL `WHERE` clause.

**Effort:** 1-2 hours
**Risk:** Low

## Acceptance Criteria

- [x] `1H:TREND > 0` correctly translates to `TREND_60 > 0` (or whatever the standard `60` min suffix is).
- [x] Unrecognized timeframes in the expression raise a clean `ValueError`.
- [x] Unit tests cover multiple timeframe alias conversions.
