# Detailed Iceberg Pipeline Stages (Medallion Architecture)

This document details the data ingestion and transformation logic for each stage of the `tvscreener` Iceberg Lakehouse.

## 1. Bronze Stage (Ingestion / "Raw")

**Purpose**: High-fidelity capture of TradingView API responses for idempotency and auditability.

*   **Source**: TradingView `/scan` API (batched in 500-symbol chunks).
*   **Storage Interface**: `pyiceberg` SqliteCatalog.
*   **Table**: `tvscreener.bronze`
*   **Partitioning**: `ingest_date` (Identity) + `ingest_hour` (Identity).
*   **Schema Policy**:
    *   Captures raw TV column names (e.g., `Recommend.All|15`, `relative_volume_10d_calc`).
    *   Includes `ingest_timestamp` and `source_batch_id`.
*   **Action**: Append-only. Every API call results in a new snapshot.

## 2. Silver Stage (Standardization / "Clean")

**Purpose**: Creating a unified, deduplicated, and standardized dataset optimized for technical analysis.

*   **Source**: `tvscreener.bronze` (Filtering for latest ingest or specific batch).
*   **Compute Engine**: `narwhals` (backend-agnostic).
*   **Table**: `tvscreener.silver`
*   **Partitioning**: `asset_type` (Identity).
*   **Transformations**:
    1.  **Deduplication**: Multi-broker data for the same pair (e.g., OANDA vs FOREXCOM) is merged using the `EXCHANGE_PRIORITY` logic.
    2.  **Column Normalization**: Mapping brittle API names to canonical technical names:
        *   `Recommend.All|{tf}` -> `trend_{tf}`
        *   `Recommend.Ma|{tf}` -> `ma_{tf}`
        *   `Recommend.Other|{tf}` -> `osc_{tf}`
        *   `Roc|{tf}` -> `roc_{tf}`
    3.  **Null Management**: Imputing neutral values (0.0) for missing technical indicators to prevent NaN-poisoning in scoring math.
    4.  **Optional Outlier Detection**: Implement Z-Score based volume outlier detection to filter anomalies. **(Disabled by default)**.
*   **Action**: Overwrite (Latest State) or Upsert.

## 3. Gold Stage (Analytics / "Scored")

**Purpose**: Production of actionable trading signals and high-value features.

*   **Source**: `tvscreener.silver`.
*   **Compute Engine**: `narwhals` + vectorized Python math.
*   **Table**: `tvscreener.gold`
*   **Partitioning**: `signal_date` (Identity).
*   **Transformations**:
    1.  **Feature Engineering**:
        *   `ENSEMBLE_SCORE`: Multi-timeframe weighted average of Trend/MA/Oscillator/ROC.
        *   `CONFLUENCE_SCORE`: Alignment count across timeframes.
    2.  **Grading Engine**: Logic mapping quantitative scores to `A+` through `F` grades.
    3.  **Strategy Detectors**: Running the Trend-Following, Mean Reversion, and Breakout detection algorithms.
    4.  **Risk Overlay**: Calculating Stop Loss, Take Profit, and Position Sizes via the `RiskEngine`.
*   **Action**: Append-only. This table serves as the permanent record of every signal generated by the system.

## Summary of Backend Interaction

| Layer | Input Format | Primary Lib | Output Format | Storage |
| :--- | :--- | :--- | :--- | :--- |
| **Bronze** | JSON List | `pd.DataFrame` | Apache Arrow | Iceberg (Parquet) |
| **Silver** | Apache Arrow | `narwhals` | Apache Arrow | Iceberg (Parquet) |
| **Gold** | Apache Arrow | `narwhals` | Apache Arrow | Iceberg (Parquet) |
| **Serving** | Iceberg Table | `duckdb` | Pandas/Markdown | Terminal / MCP |
